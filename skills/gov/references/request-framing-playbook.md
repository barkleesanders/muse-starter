## Request-framing playbook: meta-records requests (added 2026-10-06)

Standing rule: every records request for operational materials — 911 calls, dispatch audio, police reports, bodycam, CAD data, radio traffic — is drafted as TWO parallel requests in one filing:

1. **The primary materials** (the audio, the report, the footage — whatever the investigation actually wants).
2. **The "meta" request**: the downstream records the agency is legally required to create and maintain FOR the underlying event — CAD incident entries, dispatch logs, complaint/incident reports, radio logs, call disposition records, unit assignment histories.

Why: the meta request is legally unkillable. The agency cannot rule it "not a request for public records" because these are agency-created records it is mandated to keep — cite the retention authority in the request itself (in NY, the LGS-1 Records Retention and Disposition Schedule items covering dispatch/CAD/law-enforcement records; verify the current schedule live for each filing). It also defeats the "we would have to create a record" defense (the records already exist by legal duty) and blunts overbreadth challenges (the meta request is narrow: named record types tied to a date, location, and case/incident number).

**Two-track attack:** when the primary request is denied, do BOTH — appeal the denial AND file the meta-framed request as a new, separate request. The agency must then defend on two fronts under two different legal theories, and the meta request's mandated-existence argument is independent of whatever theory killed the primary. Provenance: a county FOIL request denied as "not a request for public records" — for 911 CAD/phone audio/radio tied to a set of calls to one address — is the denial pattern this playbook answers.

Drafting discipline: name each record type explicitly; tie every item to the event (date, address, incident/case number); cite the retention-schedule item; keep the primary request verbatim intact so the meta request is additive, never a narrowing. Never file either track without the user's explicit per-version approval.
